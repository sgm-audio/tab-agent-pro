# Transcription and REAPER test audit

Audited branch base `a4814b2` (2026-11-18). This is a test audit, not a certification of transcription accuracy or REAPER safety.

This records the independent PR #11 audit. The findings and counts below describe that
snapshot. See [the combined audit](TEST_AUDIT.md) for current results, test names and
commands. The merged suite uses `tests/test_reaper_contract.py` for Lua/CLI checks and
requires `tests/test_model_inference.py` in the default CI suite.

**PR #11 CI follow-up:** The original lint, formatting, type-check, Docker/env guard, quick-validation and failure-simulator issues described below have since been addressed on this branch. The index pin was independently confirmed to exist remotely and fetched for local testing. The lock now includes the transitive `huggingface-hub` dependency and updates Gradio, Pillow and Tornado to address unaccepted security advisories; obsolete Pillow exceptions were removed. Local results after these changes: 287 passed, 2 skipped, 6 xfailed; real CPU inference 2 passed; failure simulator 15/15. The six strict xfails remain unresolved product defects; these follow-up fixes do not make those safety checks pass.

## Re-verification

* Before adding tests, `pytest --collect-only -q -o addopts=''` collected **275 test cases** (268 `test_` functions; parametrization accounts for the difference), not the README's 291. After adding tests, the number changes again; it is not a quality metric.
* A local Python 3.11 run after adding the first batch produced **277 passed, 7 failed, 1 skipped, 6 xfailed**, and 92% statement coverage with `--cov=.`. It is not a clean reproduction of the claimed 91%: this command counts test and tool code, and the environment is not CI's locked Python 3.12 setup. `agents.py` reported 99% despite the defects below. The coverage run precedes two later tests. Do not compare its percentage directly with an application-only or branch-coverage figure.
* The existing failures are not new safety-test failures: two Docker guard failures disagree with the current Dockerfile's torch install; two `.env.example` guards report unused `CACHE_DIR`; `validate.py --quick` expects `os.execute` although the Lua uses `io.popen`; two index tests cannot find commit `4061696b` in this shallow checkout. The last result alone does **not** establish that the remote commit is missing or that the URLs 404.
* `tools/simulate_failures.py` reports **11/14 passed** here, not 15 working checks: it constructs `EarAgent` without `log`, constructs `SplitterAgent` without `device`, and calls the removed `_parse_mt3_tokens`. Its own exception handler turns those into failed simulations. These are broken harnesses, not evidence that the intended recovery paths were tested.
* The two bundled WAVs exist; both are three-second, 44.1 kHz mono clips. They are not labelled multitrack full mixes. `tests/test_pipeline.py::test_ear_agent_transcribes_synthetic` replaces `transcribe_stem` with a lambda; its title/docstring notwithstanding, it does not run inference. `tests/test_benchmark.py` measures generated audio processing, not accuracy. The CI backend smoke only imports Basic Pitch. Many splitter/ear tests patch either the entire separation/transcription method or `sf.write`.
* Existing `tests/test_agents_edge.py` **does** cover skipping unplayable notes and reset of `last_skipped_notes`; it does not establish chord feasibility or a globally optimal path. `tests/test_main_coverage.py` checks rendering of hand-built simultaneous positions (including same-string cells), not whether the generator can play them. Existing technique tests cover simple positive cases and a slow negative; `test_tab.py::test_technique_detection_pull_off` accepts any of slide/hammer/pull. The REAPER guard captures a command string; its `defer` is a no-op and Settings.lua is not exercised. Merely finding flags in source doesn't prove their effects.

## Findings and executable regressions

`tests/test_transcription_safety.py`, `tests/test_multitrack_contract.py`, `tests/test_reaper_safety.py`, and `tests/test_real_inference.py` implement the following. The six known-bug tests are **strict xfail**, deliberately visible in CI: they are not passing safety guarantees. Remove each marker when its underlying behavior is fixed; an unexpected pass fails the run. Prioritize P0 before relying on generated tabs or REAPER automation.

| Priority / test | Required assertion and why |
|---|---|
| P0 `test_simultaneous_playable_chord_uses_distinct_strings` (xfail) | All tones of a feasible simultaneous chord survive, reconstruct the input pitches and use different strings, without legato labels. Current DP considers one note per layer, rewarding same-string transitions even at identical onsets; rendering `/` on one string makes the collision visible but not playable. |
| P0 `test_suno_cleanup_preserves_legitimate_octave_chord` (xfail) | Preserve all pitches of a real octave voicing. Current Suno octave-cleanup unconditionally discards the upper octave; existing tests explicitly expect octave removal without a musical ground truth. This requires a policy change or confidence/evidence, not simply changing the fixture. |
| P0 `test_shell_metacharacters_in_audio_path_remain_literal` (xfail) | On POSIX, run the captured command against an inert temporary Python script; a filename containing `$(touch injected)` must arrive literally and must not execute the substitution. Current double quoting does not escape `$` or backticks. Also test install/output/profile fields and Windows separately before claiming cross-platform safety. |
| P0 `test_failed_pipeline_never_imports_stale_midi` (xfail) | Simulate EOF and nonzero exit with existing MIDI files; assert an error is shown and zero files are imported. The current poller imports before checking success. Even successful runs can import stale same-basename output, so test isolation/provenance too. |
| P1 `test_separate_picked_notes_are_not_automatically_slides` (xfail) | A definite silent gap between two notes should not produce a slide. The current heuristic looks only at onset/fret distances and throws away note end times; without acoustic evidence an unknown/pick annotation is safer than an asserted technique. Existing positive cases build the desired timing into notes. |
| P1 `test_demucs_missing_api_stem_must_not_report_success` (xfail) | Missing `bass` or `other` must trigger a typed failure/fallback rather than return a nonexistent path and mark Demucs loaded. The existing mocked API tests assert `sf.write` was called, including an API response with only one stem. |
| P0 `test_viterbi_matches_exhaustive_monophonic_minimum` | For small independent position Cartesian products, reconstruct every original pitch with in-range strings/frets/times and equal the brute-force minimum transition cost for standard, drop-D and bass. This checks backtracking beyond length/key assertions; it proves optimality only for the current **monophonic cost**, not physical playability. |
| P0 `test_skipped_notes_preserve_pitch_order_and_reset` | Low/high/repeated invalid notes interleaved with valid notes are reported in order, remaining pitch/time values survive and next call resets the report. This extends existing one-sided skip cases. |
| P1 `test_cleaner_preserves_distinct_simultaneous_chord_pitches` | Keep three distinct simultaneous pitches while dropping only an exact duplicate. Existing duplicate tests are mostly single-pitch. |
| P1 `test_demucs_double_failure_copies_actual_pcm_and_marks_unavailable` | API and CLI fail in order, real stereo PCM copies survive exactly in both paths and health is unavailable. This tests passthrough, **not separation**; guitar and bass now both contain the entire mix, which must be visible to users as degraded output. |
| P1 `test_stereo_mid_side_routing_with_distinct_tones` | Center, left and right synthetic tones produce the exact implemented mid/side equations, correct sample rate and channel routing. Existing tests mostly compare amplitudes or file existence. It does not claim true instrument isolation. |
| P1 `test_basic_pitch_failure_updates_health_and_does_not_return_empty_success` | Missing dependency during prediction raises at the public boundary and records failed health rather than returning `[]`. The current public exception misleadingly says no model is available even for runtime failures; preserve the underlying reason in future. |
| P1 `test_all_instruments_export_correct_track_notes_and_tunings` | Four distinct stubbed inference streams go through real cleanup, tab, JSON, TXT and MIDI export; assert filenames, source/target, threshold/min-pitch arguments, pitch reconstruction, drop-D/bass tunings and MIDI pitches. This is a wiring integration test, **not** real separation or inference. |
| P0 `test_settings_gui_to_lua_command_to_cli_parser` | Execute Settings.lua, persist chosen options into ExtState, execute TabAgent.lua, parse the actual captured POSIX argv with the real CLI and verify threshold precedence, instrument, profile, paths with spaces and export flags. This spans the missing Settings.lua boundary but uses a REAPER shim, not real REAPER. |
| P1 `test_real_basic_pitch_cpu_transcribes_known_tone` and `test_real_basic_pitch_cpu_silence_does_not_invent_notes` | With opt-in enabled, run the real packaged Basic Pitch ONNX model on generated A4 and silence, assert a plausible A4 and no silent-audio notes. Both passed locally. Tone tolerance is a smoke oracle, not a measure of music transcription accuracy. |

## CI and model policy

* Fast PR tests must run without network downloads and show skipped, xfailed and failed counts (`pytest -ra`, with strict xfails); report application-only **branch** coverage separately from tests/tools. Coverage is a diagnostic, never a quality or accuracy gate by itself.
* PR #11 ran unmocked CPU Basic Pitch tests in a separate opt-in invocation. In the combined suite, CPU inference runs in default pytest and needs no opt-in; missing Basic Pitch, ONNX Runtime or model weights fails the gate.
* Add a separate scheduled/release full-inference job using an offline, version-pinned and checksum-verified Demucs weight cache, pinned Basic Pitch/ONNX, and a versioned labelled corpus. Provision weights **before** the test; block network during execution. If a required model, fixture or runtime is missing, fail the job, not skip or use raw passthrough as a successful Demucs test. Record model/fixture hashes, backend, thresholds, timings, event metrics and skips as artifacts. Keep large licensed audio/weights out of Git, with explicit acquisition and licensing instructions.
* GPU is optional on ordinary PR runners: report an explicit skip with reason, while CPU real inference remains mandatory. A dedicated GPU-labelled scheduled/release runner must fail if hardware/provider/weights are missing, verify actual ONNX and Demucs GPU execution (not just device selection), and compare toleranced CPU results. A provider installed but silently falling back to CPU is not GPU coverage. Never let a skipped GPU lane or passthrough satisfy the real-inference gate.
* In the combined suite, rerun CPU inference with `python -m pytest -m basic_pitch_model -ra`, or Lua/CLI checks with `python tools/check_reaper_settings.py`. `lupa` is required for the REAPER shim, which does not substitute for a native REAPER integration run.
